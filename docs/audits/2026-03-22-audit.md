## Phase 3: Expert Design Analysis

### 3.1 Design Scoring (Code-Based)

**Visual Hierarchy (3/5):**
- Clear 3-column layout: deals panel | canvas + agent bar | chat + collaboration
- Pixel font headings create strong visual anchors
- Accent color system (teal=nav, gold=chat, coral=deals) creates semantic zones
- Weakened by very small base font size limiting readability

**Typography (2/5):**
- Font pairing is harmonious: Press Start 2P for pixel flavor + Inter for readability
- Type scale (Minor Third 1.2) is well-defined but starts too low:
  - `--text-xs: 9px` — effectively unreadable
  - `--text-sm: 10px` — too small for body content
  - `--text-base: 12px` — below 16px WCAG minimum
- 101 inline `fontFamily` declarations bypass design system fonts
- Line heights are set (1.4–1.6 range) — acceptable

**Color & Contrast (3/5):**
- Dark theme palette is cohesive with clear intent
- `--text-primary: #e0d8c0` on `--bg-panel: #0e0d1a` ≈ 11:1 contrast ratio (good)
- `--text-secondary: #8a8a9a` on `--bg-panel: #0e0d1a` ≈ 5.6:1 (passes AA)
- `--text-secondary: #8a8a9a` on `--bg-card: #14132a` ≈ 4.8:1 (borderline AA)
- 48 raw hex colors in TSX bypass design tokens

**Spacing & Layout (2/5):**
- 8-point spacing grid is well-defined (4px–32px)
- 230 raw pixel values in TSX files bypass spacing tokens
- Only 1 responsive breakpoint (1100px)
- Fixed panel widths (270px) with no collapse behavior
- No mobile layout consideration

**Interaction Design (3/5):**
- 17 hover/focus/active states defined in CSS
- 14 cursor declarations — interactive elements have proper cursors
- Consistent transition timing (0.15s for micro-interactions)
- **Zero `:focus-visible` styles** — keyboard navigation is invisible
- Buttons have hover + active states (scale transforms)

**Motion & Animation (4/5):**
- 6 defined keyframe animations (fadeSlideIn, msgIn, typingBounce, livePulse, slideInRight, pixelBlink, fadeIn)
- Durations are appropriate: 0.15–0.3s for micro, 0.5s for progress transitions
- `prefers-reduced-motion: reduce` is globally respected with universal selector override
- Animations are purposeful (typing indicators, new message entry, collaboration pulse)

**Responsiveness (1/5):**
- Single breakpoint: `@media (max-width: 1100px)` — only adjusts panel width 270px→230px
- No tablet breakpoint (768px)
- No mobile breakpoint (375px)
- Fixed 3-column layout with min-width constraints
- No touch target size adjustments
- Desktop-only design

**Empty & Error States (2/5):**
- `.chat-welcome` state with icon, heading, and description text
- `ErrorBanner` component exists for API errors
- No visible empty state for deals list, collaboration panel, or memory panel
- No loading skeleton or shimmer states in CSS

### 2. Fix Body Font Size (12px → 16px minimum)
- **Category:** a11y / design
- **Impact:** Critical — WCAG 1.4.4 text resizing, readability for all users
- **Effort:** M
- **Files:** `src/pixelDesignSystem.css` (`:root` type scale tokens)
- **Fix:** Adjust the type scale: `--text-base: 14px` minimum for UI text, `--text-sm: 12px`, `--text-xs: 10px`. The pixel font sizes can remain small for decorative headings. Update all components that hardcode font sizes.

### 3. Add ARIA Roles and Focus-Visible Styles
- **Category:** a11y
- **Impact:** Critical — WCAG 2.1.1 keyboard, 4.1.2 name/role/value. Zero `role=` attributes and zero `:focus-visible` styles means the app is unusable for keyboard/screen reader users
- **Effort:** M
- **Files:** All interactive components, `src/pixelDesignSystem.css`
- **Fix:**
  1. Add `role="button"` to all clickable `<div>` elements (agent chips, deal cards, chat tabs, etc.)
  2. Add `:focus-visible` outline style globally: `*:focus-visible { outline: 2px solid var(--accent-teal); outline-offset: 2px; }`
  3. Add `aria-label` to icon-only buttons (chat send, close buttons, zoom controls)
  4. Add landmark roles: `role="main"`, `role="navigation"`, `role="complementary"` to layout panels

### 4. Add Heading Hierarchy
- **Category:** a11y
- **Impact:** High — only 9 heading elements across entire app. Screen readers rely on headings for navigation
- **Effort:** S
- **Files:** Panel headers, modal headers, section titles
- **Fix:** Ensure each panel has an `<h2>`, each section within a panel has `<h3>`. Currently most headings are styled `<div>` elements with `.panel-title` class — convert to semantic heading elements.

### 5. Fix Color Contrast Failures (axe-core WCAG AA)
- **Category:** a11y
- **Impact:** High — 2 elements fail WCAG AA contrast requirements

  3. Add `aria-label` to both `<aside>` panels, wrap top bar in `<header>`, add `<h1>`
